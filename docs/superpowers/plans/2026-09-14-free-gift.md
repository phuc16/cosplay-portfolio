# Free Gift Feature Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sellers can configure one shop-wide free gift (name, picture, optional note, optional digital delivery link, and a minimum-order threshold) that's automatically added as a 0đ line to any qualifying order, toggleable at any time.

**Architecture:** A new singleton `gift_settings` table (mirrors the existing `payment_settings` pattern exactly) holds the config. `order_items` gets a new `is_gift` boolean. `createOrder` decides gift eligibility after computing the real paid total, and appends a gift row with `product_variant_id: NULL` and snapshot fields copied straight from `gift_settings` - no catalog relationship, no stock tracking. The frontend (Cart, Checkout) reads a public, secret-stripped view of the settings to show progress hints and to decide whether to render/require shipping fields even for an otherwise-all-digital cart.

**Tech Stack:** Node/Express, MySQL via mysql2 + Knex migrations, React/Vite, Vitest.

## Global Constraints

- One global gift, not per-collection (`docs/superpowers/specs/2026-09-14-free-gift-design.md`).
- Threshold is measured against the **items subtotal only**, before shipping fee.
- The gift has **no relationship to `product_variants`/`products`/`collections`** - it lives entirely in `gift_settings`.
- **No stock limit** - available to every qualifying order for as long as it's enabled.
- **No buyer opt-out** - added automatically, never declinable.
- **Exactly one gift unit per qualifying order**, regardless of subtotal size.
- **Digital vs. physical is inferred from whether `delivery_link` is set** - not a separate type column.
- **COD eligibility is unaffected by the gift**, in either direction - stays keyed purely on the buyer's real paid items, exactly as today.
- **A physical gift can force a digital-only order into needing shipping/pickup info.** The frontend must anticipate this before the order is submitted.
- **The gift ignores per-collection concerns entirely** - no collection status/schedule check, no `allow_ship`/`allow_pickup` check.
- `order_items.variant_label_snapshot` is `NOT NULL` - a gift row stores `""` there, and every display path must already tolerate a blank label without a dangling separator.
- Plain hyphens (` - `), never em dashes, in all new code/comments/copy.
- All buyer-facing strings go through the existing bilingual `t()`/`translations.js` mechanism; all admin-facing labels are plain Vietnamese strings, same as every other admin form in this codebase.

```js
const db = require("../db")

const DEFAULTS = {
  enabled: false, name: "", image_url: null, min_total: 0, note: null, delivery_link: null,
}

const FIELDS = ["enabled", "name", "image_url", "min_total", "note", "delivery_link"]

async function getSettings() {
  const [[row]] = await db.query("SELECT * FROM gift_settings ORDER BY id LIMIT 1")
  if (!row) return { ...DEFAULTS }
  return { ...row, enabled: Boolean(row.enabled) }
}

/** Upsert the single settings row - mirrors payments/settingsRepo.js exactly. */
async function updateSettings(data) {
  const [[existing]] = await db.query("SELECT id FROM gift_settings ORDER BY id LIMIT 1")

  const values = FIELDS.map((f) => {
    if (f === "enabled") return Boolean(data.enabled)
    if (f === "min_total") return Number.isInteger(data.min_total) ? data.min_total : 0
    if (f === "name") return data.name || ""
    return data[f] === undefined || data[f] === "" ? null : data[f]
  })

  if (existing) {
    await db.query(
      `UPDATE gift_settings SET ${FIELDS.map((f) => `${f} = ?`).join(", ")}, updated_at = NOW() WHERE id = ?`,
      [...values, existing.id]
    )
  } else {
    await db.query(
      `INSERT INTO gift_settings (${FIELDS.join(", ")}) VALUES (${FIELDS.map(() => "?").join(", ")})`,
      values
    )
  }
}

/**
 * Buyer-facing shape: no delivery_link (irrelevant pre-order - it's only
 * ever exposed once, via the buyer's own confirmed/completed order, the
 * same rule every other digital delivery link already follows). Just
 * whether the gift IS digital, so the frontend can decide whether it needs
 * to force the shipping section for an otherwise-all-digital cart.
 */
function publicSettings(settings) {
  return {
    enabled: settings.enabled,
    min_total: settings.min_total,
    name: settings.name,
    image_url: settings.image_url,
    note: settings.note,
    is_digital: Boolean(settings.delivery_link),
  }
}

module.exports = { getSettings, updateSettings, publicSettings, DEFAULTS }
```

const express = require("express")
const repo = require("../shop/giftSettings")

function validate(d) {
  if (d.enabled) {
    if (!d.name?.trim()) return "Cần tên quà tặng"
    if (!Number.isInteger(d.min_total) || d.min_total < 0) {
      return "Mức đơn tối thiểu phải là số nguyên không âm"
    }
  }
  // adminUploadImage (the only way this field is populated through the UI)
  // always returns storage.proxyUrl()'s relative "/api/storage/..." path,
  // same as every other image field in the app.
  if (d.image_url?.trim() && !/^(https?:\/\/|\/api\/storage\/)/i.test(d.image_url.trim())) {
    return "Ảnh quà tặng phải là URL http:// hoặc https://, hoặc ảnh tải lên từ hệ thống"
  }
  return null
}

module.exports = function adminGiftRoutes() {
  const router = express.Router()

  router.get("/gift-settings", async (req, res) => {
    try {
      res.json(await repo.getSettings())
    } catch (err) {
      console.error("[ADMIN/GIFT] Lỗi đọc cấu hình:", err)
      res.status(500).json({ error: "server_error", message: "Lỗi server. Thử lại sau." })
    }
  })

  router.put("/gift-settings", async (req, res) => {
    try {
      const invalid = validate(req.body)
      if (invalid) return res.status(400).json({ error: "invalid_input", message: invalid })

      await repo.updateSettings(req.body)
      res.json({ ok: true })
    } catch (err) {
      console.error("[ADMIN/GIFT] Lỗi lưu cấu hình:", err)
      res.status(500).json({ error: "server_error", message: "Lỗi server. Thử lại sau." })
    }
  })

  return router
}

Every existing test asserts against a single bad line at a time, so this does not break any of them - noted here so it isn't mistaken for an unintended regression during review.
