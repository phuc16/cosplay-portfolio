# Wishlist (Save-for-Later) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A buyer can heart-toggle a variant to save it for later, see a live count badge in the shop header, and browse/manage saved items on a new `/merchandise/wishlist` page that always shows live price/stock, distinct from both the cart (checkout-bound, snapshot, has qty) and the separately-shipped back-in-stock email alert (server-side, one-shot, tied to a single sold-out variant).

**Architecture:** A new client-only module `frontend/src/shop/wishlist.js` mirrors `cart.js`'s localStorage + subscribe/notify shape exactly, but stores pointers (`variant_id`, `product_id`, `collection_slug`) rather than a price/name snapshot. `ProductCard.jsx` gets a heart toggle in its variant-gallery thumbnails and its detail modal. `ShopHeader.jsx` gets a wishlist nav icon with a live count badge, mirroring its existing cart badge. A new `Wishlist.jsx` page re-fetches each saved item's collection by slug (same resilient per-slug-fetch pattern `cartAvailability.js` already uses) and renders live data, never the cached cosmetic fields. No backend changes.

**Tech Stack:** React/Vite, Vitest, this codebase's raw `createRoot`/`act` component-test idiom (no `@testing-library/react`).

## Global Constraints

- 100% client-side - no backend route, no migration, no `backend/` changes at all (`docs/superpowers/specs/2026-09-22-wishlist-design.md`).
- No `qty`, no merge-on-duplicate - a variant is either saved or not.
- Wishlist entries are **not** a price/availability snapshot - `Wishlist.jsx` always re-fetches live data by `collection_slug` before rendering anything actionable.
- The heart toggle is **never** disabled by sold-out/closed/not-started state - the opposite of "Add to cart".
- Reuse the existing `addToCart` (from `shop/cart.js`) for the wishlist page's quick-add action - no reimplementation.
- All buyer-facing strings go through `translations.js`'s `t()` - no hardcoded copy in JSX.
- Plain hyphens (` - `), never em dashes, in all new code/comments/copy.
- Do not confuse this with PR #11 (back-in-stock email alerts) - no shared code or data between the two.
